# IM 入口复核方案（口径 B：本机也该能开）

- 缺陷：用户装了新包找不到 IM 入口（用户截图 + PM 派单）
- 根因（PM / UI设计师 / 前端三方独立定位一致）：`WorkspacePageRail.tsx:74` 读 `activeServer()?.compatibility?.capabilities ?? []`，而**本地实例的 `compatibility` 被写死 `null`**（`src/main/remote-server-summaries.ts:32`）→ 能力清单空 → `imEntrySupport` 七位全 false → `onIm` undefined → **图标连「⋯ 更多」菜单都不进**
- 不一致点：其它功能走 `serverSupportsCapability()`（`server-capabilities.ts:173`，**本机一律算支持**），只有 IM 这条按「必须显式声明」判
- **PM 拍口径 B**：本机也该能开 IM 页（本地实例自己就是 IM 实现方，16 能力 44+ route 全通）

## 一、复核的两条硬对照（PM 点名）

| # | 对照 | 期望 | 为什么必须有 |
| --- | --- | --- | --- |
| **1** | **本地实例有 IM 能力 → 图标出现** | 左侧窄栏（或「⋯ 更多」菜单）出现 `MessagesSquare` 图标 + 文案「IM」，点得进四段 | 正向：修复确实生效 |
| **2** | **远端没声明 im-\* → 图标仍不出现** | `compatibility.capabilities` 不含 `im-peers-v1`/`im-messages-v1` 时，图标**不渲染**（不是灰掉、不是点了报错） | **反向：防止顺手放宽门控**——60 天那条「旧 host 缺 im-\* 时全端不显示入口、无点击路径、无失败提示」必须仍成立 |

**对照 2 是关键**。修复容易做宽（比如「本机一律算支持」写到通用判法上），那样远端旧实例也会露出入口，违反 Team API 60 天兼容。所以两条都要在**同一次验证**里跑。

## 二、证据形态要求

**必须来自打包产物真应用，不是单测。** 具体：
- 装 `dist/OpenBot-0.75.0-arm64.dmg`（未签名，右键→打开或 `xattr -dr com.apple.quarantine`）
- **截图 A**：本地服务器激活时，左侧窄栏（或「⋯ 更多」展开后）**真能看到 IM 图标**
- **截图 B**：点进去后四段（收件箱 / 联系人 / 会话 / 设备）真渲染
- **截图 C（对照）**：切到一台**未声明 im-\* 的远端**时，同一条窄栏**没有** IM 图标

单测只能验 `imEntrySupport` 的判定函数——**上一轮「七段全开 + 4 段」就是这么验的，结果没走真实应用取值路径，缺陷漏了**。这次不接受单测。

## 三、第三条用户可达路径（UI设计师 指出，一并验）

**设置 → 应用行为 → 页面最底部「IM」小节**（代聊/代理、通知与免打扰、可被搜索）。
这一处**不受能力门控**，是当前唯一进得去的 IM 入口。要验：
- 修前后它都可达（不受门控回归影响）；
- 修后它与主入口（左侧栏 IM 页）**不打架**——同一设置在两处的读写一致（UI设计师 建议两处互链或独立成一级，属设计整改，非本轮验收）。
