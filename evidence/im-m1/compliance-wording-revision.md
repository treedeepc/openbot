# 合规矩阵措辞修订 —— 「不显示入口」放宽为「不提供可用入口」

- 修订人：产品经理（PM 拍板）
- 记录人：测试工程师
- 影响用例：`scripts/verify-im-entry-gate.ts`（对照 2）
- 关联关卡：T14a M1（入口缺陷那条）；T14e M7 的 M7-08/09/10 三条能力缺失用例

## 一、原条文与新条文

| | 措辞 |
| --- | --- |
| **原** | 「旧 host 缺 `im-*` 时**不显示入口**、无点击路径、无失败提示」 |
| **新** | 「**不提供可用入口**（不渲染，**或**渲染为不可点击的禁用态并说明原因）、无点击路径、无失败提示」 |

## 二、修订理由（PM 原话要点）

1. **静默隐藏刚造成真实成本**：用户装了包找不到 IM 入口，三个人独立查根因才发现是门控把入口判没了——**完全没痕迹**，用户只会以为功能没做。
2. **禁用态在精神上符合原意**：原条文的目的是「不让人以为能用」。渲染成禁用 + 说明「当前服务器未提供 IM」，同样是不让人以为能用，且**多给了「为什么没有」这一信息**。
3. **另两条仍守得住**：「无点击路径」「无失败提示」一字未动——禁用态不可点，也就不会有点了报错的可能。

## 三、这个修订**没有放宽什么**

| 仍然严格 | 说明 |
| --- | --- |
| **解析器层口径未变** | `imEntrySupportFor` 对远端仍**严格按声明清单**判，七位全否就是全否 |
| **无点击路径** | 禁用态不可点，与「不渲染」等价于「点不到」 |
| **无失败提示** | 不会出现「点了报错」 |
| **不能因此多声明能力** | 「未实现 capability 不声明」红线不动 |

**放宽的只是「渲染形态」这一层**：从「必须不渲染」变成「不渲染 或 禁用+说明」，二选一都算合规。

## 四、解析器层 vs 渲染层：各自验什么（前端点出的分工，写清）

前端指出：对照脚本验的是**解析器**，渲染层改成了**渲染但禁用**，两者不矛盾。**确实不矛盾，但验的东西不同**：

| 层 | 验什么 | 谁验 | 本轮归属 |
| --- | --- | --- | --- |
| **解析器层** | `imEntrySupportFor(server)` 的七位判定——能力在不在、判真判假 | `scripts/verify-im-entry-gate.ts`（走真实 `remoteServerSummaries` 产出的 summary） | **测试**（本轮已更新口径） |
| **渲染层** | 判否时**怎么显示**——不渲染 还是 禁用+说明；禁用态的按钮属性、说明文案 | 前端截图 / 真应用证据 | **前端** |

**两层的接缝**：渲染层的 `disabledReason` **由同一个谓词派生**——
`WorkspacePageRail.tsx:79` = `imEntrySupportFor(activeServer()).session ? undefined : t("im.entry.unavailable")`
`WebWorkspace.tsx:1342` = `imPort() && imEntryAvailable(imSupport()) ? undefined : t("im.entry.unavailable")`

**所以解析器判否 ⇔ 按钮被置为禁用**，不是两套判法。这也是下面那条对照能成立的依据。

## 五、对照 2 的新断言（`verify-im-entry-gate.ts`，现 17/17）

| 断言 | 验什么 | 结果 |
| --- | --- | --- |
| 解析器判否：没有可用入口（无点击路径） | `railFormOf !== "openIm"` 且 `imEntryAvailable === false` | ✅ |
| **形态合规：不渲染 或 禁用+说明，两种都接受** | 只要不是可用入口，两种渲染形态都算过 | ✅ |
| **禁用态确实发不出请求** | 门控谓词为假（`imEntryAvailable === false` 且 `session === false`）→ 按钮不得启用 | ✅ |
| **对照的对照**：能力齐备时同一谓词放行 | `imEntryAvailable === true` 且 `railFormOf === "openIm"` | ✅ |
| 七项全否（没被顺手放宽） | 原有 | ✅ |
| 远端门控路径未被改动 | 原有 | ✅ |

**「禁用态确实发不出请求」这条的证明边界（如实标）**：它证的是**门控谓词为假 + 无可点击动作**，配合同一谓词派生 `disabledReason` 的接缝，可推出按钮处于禁用态、点不出请求。**按钮的 `disabled` DOM 属性本身属渲染层**，由前端截图与真应用证据覆盖，不在本脚本内。
